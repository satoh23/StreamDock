# リリースノート（`docs/release-notes/`）

**このディレクトリがリリースノートの単一ソース**（055a）。1 リリース 1 ファイルで `vX.Y.Z.md` を置く。

CI（[`release.yml`](../../.github/workflows/release.yml) の `Generate latest.json`）が、このファイルの内容を

- `latest.json` の `notes` … アプリ内アップデート画面に表示される更新内容（055c/055e）
- GitHub Release の本文 … `satoh23/StreamDock-releases` の Releases ページ

の**両方**へそのまま流す。GitHub の Release 本文を後から編集しても `latest.json` には反映されないので、
**書くのは必ずこのファイル**。

## 運用ルール

- ファイル名は **`tauri.conf.json` の `version` に `v` を付けたもの**（例: `0.2.0` → `v0.2.0.md`）。
  CI はタグ名ではなくこの規則でファイルを探す。
- **タグを打つ前に書く。** タグ push 時にファイルが無いと **CI が fail する**（リリースノート無しの配信を防ぐため）。
- 書いてよいのは**公開してよいリリース説明のみ**。ローカルパス・環境情報・Secrets・内部の URL は書かない
  （[`docs/security.md`](../security.md) §9）。

## 書ける記法

アプリ内の表示は**自前の最小マークダウンレンダラ**（055e・新規依存ゼロ・
[`renderReleaseNotes.tsx`](../../apps/desktop/src/screens/app-update/renderReleaseNotes.tsx)）で
描画するため、**下の記法だけ**を使うこと。それ以外はそのままの文字として表示される
（壊れはしないが整形もされない）。

| 記法 | 用途 | アプリでの見え方 |
| --- | --- | --- |
| `# 見出し` / `## 見出し` / `### 見出し` | 見出し 3 段 | いずれも太字。`#` が本文より大きく、`##` は本文と同じ大きさ、`###` は少し小さい |
| `- 項目`（`* 項目` も同じ） | 箇条書き（**ネストしない**） | **行頭**に `-`（または `*`）＋**半角スペース**。字下げすると箇条書きにならない |
| `**太字**` | 強調 | 太字 |
| `` `コード` `` | インラインコード（設定名・ファイル名など） | 枠付きの等幅チップ |

- **改行するとそこで段落が変わる。** 空行を入れなくても行は分かれるので、1 行に 1 つのことを書く。
  ⚠ 長い項目を**途中で改行して続きを書かない**（続きの行は別の段落として表示される）。
- **空行**はブロックの区切り。箇条書きを閉じたいとき・見出しと本文を離したいときに入れる。

**使わないもの**: 表・引用・コードブロック（```）・画像・水平線・ネストした箇条書き・脚注・
番号付きリスト。
**リンク（`[text](url)`）も使わない**——アプリ側では踏めず、テキストとして表示されるだけ（055e の決定。
外部 URL を開く面を増やさないため）。

> これらは**消えも壊れもしない**（そのままの文字として出る）が、整形もされないので読みにくくなる。

⚠ **チェックボックス（`- [ ] …`）だけは例外で、「そのままの文字」にならない。** 行頭の `- ` が
箇条書きとして拾われるため、**`- ` が消えて `[ ]` だけが残る**（チェックボックスにはならない）。
使わないこと。

## 雛形

```markdown
## 新機能

- **○○** ができるようになりました。

## 改善

- ○○の表示を見やすくしました。

## 修正

- ○○が動かないことがある不具合を直しました。
```

見出しは必要なものだけでよい（3 つとも書く必要はない）。ユーザーが読むものなので、
内部の課題番号やファイル名ではなく**何ができるようになったか**を書く。
