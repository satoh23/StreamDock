## 目的

依頼者の要望⑦は「**たぬえさよりかなり簡単に**作成できるようにする」であり、
**「たぬえさの何が面倒なのか」が確定しないと、簡単にしたつもりで同じものを作る**。

本スパイクで確定させるのは 1 つだけ：**StreamDock 側の作成 UI を「表 1 枚」に落とせるか、
落とせるならその表の列は何か。**

## 現在の前提（Web 調査・一次確認が要る）

- **たぬえさ3 は Twitch 専用の無料自動化 BOT**。チャット / チャンネルポイント / ビッツ / サブスクに反応して
  画像・音・動画を出す。
- **ガチャの設定手順**（解説記事ベース）:
  1. トリガーを選ぶ
  2. **抽選箱**を作る
  3. **抽選タグ**を作る
  4. ⚠ **タグをコピー＆ペーストで増やす**
  5. 各タグにメディア（画像/音声）を設定
  6. 保存
- **OBS への出し方**: OBS のソース → ブラウザ → 「ローカルファイル」→ たぬえさ3 フォルダの **`forOBS3.html`**。
- OBS WebSocket でシーン切替・ソースの表示/非表示も操作できる。
- ⚠ **依頼者の「if 文をたくさん書かないといけない」は伝聞**（「らしい」）。
  条件式を書くのか、上記 4. の手作業コピペを指すのかが**未確定**。**本スパイクの中心論点。**

## このタスクでやること（検証項目）

### (1) 「if 文をたくさん書く」の実体を特定する ← ⚠ 最重要

- 公開ドキュメント／Wiki／解説記事で、ガチャ設定に**条件式やスクリプトの記述が必要か**を確認する。
- 必要なら、**何を書かされるのか**（トリガー条件・分岐・変数）を具体的に把握する。
- 不要なら、面倒さの正体は**手順 4.（タグのコピペ）**か、**画面をまたぐ手数**のはず。
- → **結論を 1 文で書く**: 「たぬえさ3 でガチャを作るとき、配信者が一番手間だと感じるのは ◯◯ である」

### (2) 確率・重みの指定方法

- **本数指定（10 本中 3 本）か、％指定か、重み指定か。**
- **合計を 100% にする作業をユーザーがやるのか**（やるなら、そこは StreamDock で自動化する価値が高い）。
- 景品を 1 つ足したときに**他の景品の設定も直す必要があるか**（あるなら、そこが最大の面倒さ）。

### (3) 景品 1 件あたりに設定する項目の数

- 名前 / メディア / 音 / 表示時間 / その他。
- ⚠ **StreamDock の表の列を決めるための項目**。多すぎるなら削り、足りないなら足す。

### (4) トリガーの種類と、チャンネルポイント依存度

- たぬえさ3 のガチャが**主にチャンネルポイントで回されている**のかを確認する。
- ⚠ **StreamDock はチャンネルポイントを扱えない**（新規 EventSub 購読＋新規スコープ＝既存ユーザーの再ログイン）。
  → **主用途がチャンネルポイントなら、StreamDock のガチャは「代替」にならない**。
  その場合は **(a) チャンネルポイント対応を別タスクとして起票する (b) 課金トリガー限定として出す
  (c) 063 系を保留にする** の 3 択を本人に提示する。
  ⚠ **これは 063 の存在価値を左右する**ので、必ず確認して結論に書く。

### (5) OBS への出し方の差と、その影響

- たぬえさ3 = ブラウザソース（`forOBS3.html` をローカルファイルとして読む）。
- StreamDock = **ウィンドウキャプチャ**（[044s](044s-obs-websocket-spike.md) で方式 A を実測決定）。
- → **セットアップ手順がどう変わるか**を整理する。
  ⚠ StreamDock は [044a](044a-obs-auto-source-impl.md) で**ソースの自動追加**まで済ませているので、
  **ここは StreamDock のほうが手順が少ない**はず。**差別化点として記録する。**

### (6) 対応プラットフォーム

- たぬえさ3 は **Twitch 専用**。StreamDock は **YouTube + Twitch**。
- → **YouTube 配信者にとっては「たぬえさの代替」ではなく「唯一の選択肢」**になる。
  **これも差別化点として記録する。**

### (7) StreamDock 側の設計目標を確定する

上記を踏まえ、**[063a](063a-gacha-definition-editor.md) の作成 UI を「表 1 枚」に落とせるか**を判断する。

想定する表（**[063s](063s-tanuesa-gacha-spike.md) の結果で列を確定させる**）:

| 景品名 | 重み | 確率（自動計算・編集不可） | エフェクト |
|---|---|---|---|
| 大当たり | 1 | 10.0% | （テンプレート選択） |
| 当たり | 3 | 30.0% | 〃 |
| はずれ | 6 | 60.0% | 〃 |

- ⚠ **「条件を追加」ボタンを作らない。** 行を足す＝景品を足す、だけ。
- ⚠ **確率は常時表示・自動計算**。合計 100% にする作業をユーザーにさせない。
- → **この形で (1) の「一番手間だと感じること」が実際に消えるか**を検証し、消えないなら設計を作り直す。
