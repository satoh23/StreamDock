## このタスクの範囲

**「OBS に置いてあるソースを StreamDock から 1 回鳴らせる」ことを確かめられる状態にする**まで。

⚠⚠ **コメントでの自動発火は入れていない**（064b）。理由は 2 つ:

1. 先に確かめたいのは **「非表示 → 表示 ＋ 頭出しで、メディアソースが期待どおり先頭から再生されるか」**で、
   これは**実機でしか分からない**（開発機に OBS が要る）。
2. 自動発火には**接続の維持**が要る（下記）。それは docs/security.md への姿勢の追補を伴う別の判断である。

## ⚠⚠ 設計上の要点

### 1. main 窓は OBS へ直接触れない（構造上の非対称）

sidecar と WS で繋がっているのは**コメビュ窓だけ**。⇒ main 窓は **localStorage に依頼を書き、
コメビュ窓が代行する**。⚠ これは **061a が予告していた再修正トリガー**
「main 窓でも結果を見たくなったら localStorage へ 1 キー足す」の発火である。

⚠ 伝達は `storage` イベント＝**別 webview 間ではベストエフォート**。届かなかったときの壊れ方は
「**更新ボタンを押しても一覧が変わらない**」に留まる（無言で誤動作しない）。

### 2. 「消す」責任を 1 か所に閉じる

⚠⚠ **表示だけして消し忘れると、配信画面に出しっぱなしになる**——この機能で最悪の壊れ方。
⇒ `fireSource` が **表示・頭出し・消すタイマー・接続の後始末**をすべて持つ
（⚠ 064b で**消すまでの長さを OBS に聞く**ようになったが、**クランプは残っている**）:

- 同じソースの**再発火では前のタイマーを捨てて張り直す**（捨てないと、出した直後に消える）
- **接続は消し終えるまで保持**する（消すためだけに繋ぎ直さない）
- 表示時間は**拒否ではなくクランプ**（不正値でも必ず有限時間で消える）

### 3. 鳴らせる種別は allow-list

`ffmpeg_source`（メディアソース）と `image_source`（画像）だけ。
⚠⚠ **`browser_source` は入れていない**——他ツールの HTML エフェクトを鳴らせる魅力はあるが、
頭出しが別 API（`PressInputPropertiesButton`）になり操作面が増える。
**再修正トリガー＝「ブラウザソースを鳴らしたい」と言われたとき**（§3 の再評価と security-review が要る）。

## ⏳ 実機で確認すること（**このタスクの本題**）

1. コメントビューアを開き、OBS と接続する
2. OBS の**現在のシーン**にメディアソース（mp4 など）を 1 つ置く
3. 「OBSエフェクト」画面 →「OBS のソースを鳴らす」→ **「OBS のソースを取得」**で一覧に出るか
4. **「1 回鳴らす」で、先頭から再生されて 5 秒で消えるか**
   - ⚠ 特に **2 回続けて押したときに、2 回目がちゃんと頭出しされるか**
   - ⚠ **消えたあと、OBS のソースが「非表示」で残る**（削除されない）こと
5. 現在のシーンに**置いていない**ソースを鳴らそうとしたときに、コメビュ側で失敗が読めるか

⚠ ここで期待と違ったら **064b の作りが変わる**ので、先に必ず確かめること。
