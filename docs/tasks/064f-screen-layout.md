## ⚠⚠⚠ 1 は `docs/security.md` §1 の停止導線だった

§1 が要求するのは「**取得が続いていることと、その止め方**を明示する導線を保つこと」で、
061k 以降その導線は **`ObsEffectsScreen` と `MainScreen` の 2 か所**にあった
（061i レビュー S-1 が「**片方だけ直さないこと**」を明文化している）。

### ⇒ **要求を後退させずに消せる**と判断した

| | 条件 | 正確さ |
|---|---|---|
| `ObsEffectsScreen`（**消した**） | `viewerOpen === false` だけ | ⚠ **無条件に「取得が続く」と断言**していた |
| `MainScreen`（**残した・無改変**） | `isStageOverlayOpen()` を**実際に見る** | ✅ 条件付きで**正確** |

⚠⚠ **実際に取得が続くのは「ステージ窓が開いているとき」だけ**である
（sidecar の消費者は `comment-viewer` と `stage-overlay` の 2 つ）。
⇒ 消した側は **ほとんどの場合その案内が不正確**で、しかも §1 自身が書いている
「**条件付きであることを落とさずに書くこと**」に**自分で違反していた**。

⇒ **精度の低い方を消し、高い方だけを残した。** §1 本文を「導線は `MainScreen` の 1 か所」へ改訂し、
⚠ **「2 か所目を足すなら必ず実際の条件を見て分岐する形にすること」**を書き足した。

## ⚠ 代わりに置いた案内

> OBSエフェクトは「コメントビューア for StreamDock」の専用機能です。
> ご利用の際はコメントビューアを起動し、配信に接続してください。

＋「コメントビューアを開く」ボタン。

- ⚠ **出すのは `viewerOpen === false` のときだけ**——開いている人に「起動してください」は
  それ自体が嘘（061a レビュー Q-1 の「約束できることだけ書く」）。
- ⚠ この文は**この機能を使うのに何が要るか**だけを述べ、**取得の継続には触れない**（指示どおり）。
- ⚠ 窓名は Rust の `.title("コメントビューア for StreamDock")` と一致させること
  （`AddToolScreen` にも同じ直書きの先例がある）。

## ⚠⚠ 4 は「移動」では済まなかった

取得ボタンが**タイトル行**、一覧と状態の案内が**カード**、と**同じ状態を 2 か所が読む**形になった。
⇒ どちらか片方に state を置くと **「押したのにカードが『取得中』にならない」**という食い違いが
**構造的に作れてしまう**（061d-2 レビュー Q-9 と同型）。

⇒ **`useObsSourceList` フックを新設**し、**持ち主を `ObsEffectsScreen` 1 つ**にした:

| | 持つもの |
|---|---|
| `useObsSourceList`（新規） | `list` / `status` / `refresh` / `blocked`・`storage` 購読・8 秒タイマー |
| `ObsEffectsScreen` | フックを呼び、**ボタンをタイトル行**へ・**状態をカード**へ渡す |
| `ObsSourceCard` | ⚠ **表示専用**（state もタイマーも購読も持たない） |
| `obsSourceListStatus`（純関数） | ⚠ **無改変**——状態の決め方は 1 か所のまま |

⚠ ボタンの器は既製の `layout.actions`（`RakurakuToolsScreen` などと同じ）＝**新しい px を発明しない**。

⚠ 「HH:MM 時点」は**一覧の側（カード）へ移した**——ボタンの隣に置くと、画面最上部に
「12:34 時点」だけが浮いて何の時刻か読めない。
