## このタスクでやること

### (1) 一覧を返すコマンド（⚠ `StreamSummary` には**混ぜない**）

`gacha_history` モジュール（063h が作る）に **`list_gacha_draws(session_id) -> Vec<GachaDrawRecord>`** を足す。
**`drawn_at` の降順**（レイド一覧と同じ並び）。

⚠⚠ **`StreamSummary` に配列を足さない理由**:

1. あの型の doc は「**1 つの行集合から導出している**」という**数字の担保**を説明している。
   母集合の違う配列を同居させると、**その説明が読み手に効かなくなる**。
2. ガチャの行数は**課金やレイドと桁が違いうる**（キーワード条件を広く張れば毎コメント抽選が起きる）。
   ⇒ 将来「上限」「ページング」を入れるときに、**課金集計の DTO を触ることになる**。
3. 063h は独立したモジュールなので、**`stream_summary` が新テーブルを知らずに済む**。

⚠ **画面は invoke を 2 本並行に投げる**（`get_stream_summary` と `list_gacha_draws`）。
⚠⚠ **どちらか一方が失敗しても、もう一方は出すこと**——「ガチャが取れないと配信サマリーごと出ない」は
本タスクが作ってよい退行ではない。
⚠ **先例は `Promise.allSettled`** ——`ViewersView` の一括削除（⚠ **失敗があれば件数だけを画面に出す。
本文・エラー詳細は出さない＝§9**）と `effectOverlayRestore` の 2 本がある。**同じ作法に揃えること。**

DTO（`GachaDrawRecord`・camelCase・ts-rs の出力先は
**`src/features/comment-viewer/bindings/`**・⚠ 既存 6 ディレクトリの外へ出さない）:

| フィールド | 中身 |
|---|---|
| `id` | 記録 id |
| `viewerId` | `provider:providerUserId`（⚠ **視聴者詳細へ渡すため**） |
| `viewerName` | **抽選した時点の**表示名 |
| `gachaName` | 抽選した時点のガチャ名 |
| `prizeLabel` | ⚠ **`null` ＝ 何も出なかった**（`#[ts(optional)]`） |
| `rare` | レアだったか |
| `drawnAt` | RFC3339 |

### (2) 画面（`SummaryView` に「ガチャ」節を足す）

- 位置は **レイド一覧の下**（＝「マスト要件」の 2 つを上に残す）。
- 見出しは **「ガチャ」**。行は **時刻／引いた人／ガチャ／結果** の 4 列。
  - **結果** … 景品名。⚠ `prizeLabel` が `null` なら **「何も出ない」**
    （⚠⚠ **文言をここに書かない**——063h が共有した定数を使う。設定画面のテスト抽選と**同じ言葉**であること）。
  - **レア** … ⚠ 別の列にしない。**結果の隣のバッジ**（`✨レア✨` ではなく画面の意匠に合わせる）。
    ⚠ 列を増やすと横に伸びて読めなくなる（この窓は配信中に開く）。
- ⚠⚠ **引いた人の行から視聴者詳細へ飛べるようにする**（貢献者一覧と**同じ導線**を再利用）。
  ⚠ **`viewers` に行が無い場合がある**（063h は FK を張らない）ので、
  **詳細が引けなかったときに画面が壊れないこと**（穴 C）。
- **空のとき**: 「ガチャはありません」の 1 行。
  ⚠⚠⚠ **「この配信より前の記録はありません」等の説明文を書かない**（注記全廃の決定）。
- **件数が多いとき**: ⚠ **画面側で直近 N 件に切り、切ったことを画面に出す**
  （062c が `list_stream_sessions` を直近 20 件に切ったときと**同じ作法**。Rust は触らない）。
  N は実装時に決めて**定数 1 か所**に置く。

### (3) テスト

- **frontend（vitest）**
  - 何も出なかった行が **「何も出ない」**として出る（⚠ 「ハズレ」という語が画面に無いことも固定）。
  - レアのバッジが出る／出ない。
  - 空のときの 1 行。
  - ⚠ **上限で切ったときに「切った」ことが画面に出る**。
  - ⚠⚠ **`list_gacha_draws` が失敗しても、課金・レイドの節は出る**（(1) の規律）。
  - ⚠ 既存ガード（**長い説明文を出さない**）に引っかからない。
- **Rust（cargo test）**
  - 並び順（`drawn_at` 降順）。
  - 別セッションの行が混ざらない。
  - `prize_label` が NULL の行が `None` として返る。

## このタスクでやらないこと

- **期間サマリー（[062d](062d-stream-history-filter.md)）へのガチャの合流**。
  ⚠ 申し送りだけ書く（**月別・年別で「誰が何を引いたか」を出すなら母集合の定義を先に決める**こと。
  062d が「配信別と月別で数字が食い違わないように定義を揃えろ」と申し送っているのと同じ問題が起きる）。
- **視聴者詳細（`ViewerDetailPanel`）にガチャ履歴を出す**こと。⚠ 要望は「配信サマリー」なので範囲外。
- **集計**（誰が何回引いたか・景品ごとの実測確率）。⚠⚠ **実測の相対確率は出さない**
  （[gachaDraw.ts](../../apps/desktop/src/screens/obs-effects/gachaDraw.ts) の穴 D の決定は不変）。
- **エクスポート／CSV**、**メールの導線**（[063g](063g-gacha-prize-mail-spike.md) の結論次第で 063j 以降）。
- **過去の配信への遡及**（記録は遡れない＝古い配信のサマリーは必ず空になる）。
