## 目的

依頼者の要望（2026-08-30・原文）:

> その配信で行われたガチャについて、誰がガチャを引いて誰が何を引いたのかを
> **配信サマリーで確認できるようにしたい**。

⚠⚠ **「誰が引いたか」も出す**（[063h](063h-gacha-draw-recording.md) が
**何も当たらなかった抽選も 1 行として記録する**ため）。
⚠ 画面に「ハズレ」という語は出さない——**「何も出ない」**（既存の `MISS_LABEL`）で統一する。

## 現在の前提（⚠ 実コードで確認済み・2026-08-30）

- サマリーは **`get_stream_summary(session_id)` 1 本**
  （[stream_summary/commands.rs:31](../../apps/desktop/src-tauri/src/stream_summary/commands.rs#L31)）で
  `StreamSummary`（この配信／数字／貢献者一覧／レイド一覧）を返す。
- ⚠⚠ **数字の担保**: `monetary_by_kind` / `monetary_by_currency` / `monetary_total_count` は
  **1 つの行集合から導出している**（別々のクエリにしていない）＝
  「通貨ごとの count の合計 ≠ 総課金回数」が構造的に起こり得ない
  （[stream_summary/model.rs](../../apps/desktop/src-tauri/src/stream_summary/model.rs) の `StreamSummary` の doc が正）。
- 画面は [SummaryView.tsx](../../apps/desktop/src/screens/comment-viewer/SummaryView.tsx) で、
  節は **「この配信」→「数字」→「貢献者一覧」→「レイド一覧」**の順
  （[:318](../../apps/desktop/src/screens/comment-viewer/SummaryView.tsx#L318) /
  [:380](../../apps/desktop/src/screens/comment-viewer/SummaryView.tsx#L380) /
  [:436](../../apps/desktop/src/screens/comment-viewer/SummaryView.tsx#L436) /
  [:489](../../apps/desktop/src/screens/comment-viewer/SummaryView.tsx#L489)）。
- **貢献者の行から視聴者詳細（`ViewerDetailPanel`）へ飛べる**（038b の導線を再利用している）。
- 空のときは **1 行の短文**（例: 「レイドはありません」）。
- ⚠⚠⚠ **注記（説明文）は 2026-08-16 に全廃されている**（親 062 (3) の反転）。
  **歪みは文章ではなく構造で示す**——`SummaryView.test.tsx` に
  「画面に長い説明文（注記）を出さない」というガードがある。
- ⚠ **SQL は完全な文字列リテラルのみ**（`stream_summary` は `grep format!` が実コードで **0 件**であることを
  担保にしている）。**新モジュールでもこの性質を壊さないこと**（§8）。

## このタスクでやること

### (1) 一覧を返すコマンド（⚠ `StreamSummary` には**混ぜない**）

`gacha_history` モジュール（063h が作る）に **`list_gacha_draws(session_id) -> Vec<GachaDrawRecord>`** を足す。
**`drawn_at` の降順**（レイド一覧と同じ並び）。

⚠⚠ **`StreamSummary` に配列を足さない理由**:

1. あの型の doc は「**1 つの行集合から導出している**」という**数字の担保**を説明している。
   母集合の違う配列を同居させると、**その説明が読み手に効かなくなる**。
2. ガチャの行数は**課金やレイドと桁が違いうる**（キーワード条件を広く張れば毎コメント抽選が起きる）。
   ⇒ 将来「上限」「ページング」を入れるときに、**課金集計の DTO を触ることになる**。
3. 063h は独立したモジュールなので、**`stream_summary` が新テーブルを知らずに済む**。

⚠ **画面は invoke を 2 本並行に投げる**（`get_stream_summary` と `list_gacha_draws`）。
⚠⚠ **どちらか一方が失敗しても、もう一方は出すこと**——「ガチャが取れないと配信サマリーごと出ない」は
本タスクが作ってよい退行ではない。

DTO（`GachaDrawRecord`・camelCase・ts-rs の出力先は
**`src/features/comment-viewer/bindings/`**・⚠ 既存 6 ディレクトリの外へ出さない）:

| フィールド | 中身 |
|---|---|
| `id` | 記録 id |
| `viewerId` | `provider:providerUserId`（⚠ **視聴者詳細へ渡すため**） |
| `viewerName` | **抽選した時点の**表示名 |
| `gachaName` | 抽選した時点のガチャ名 |
| `prizeLabel` | ⚠ **`null` ＝ 何も出なかった**（`#[ts(optional)]`） |
| `rare` | レアだったか |
| `drawnAt` | RFC3339 |

### (2) 画面（`SummaryView` に「ガチャ」節を足す）

- 位置は **レイド一覧の下**（＝「マスト要件」の 2 つを上に残す）。
- 見出しは **「ガチャ」**。行は **時刻／引いた人／ガチャ／結果** の 4 列。
  - **結果** … 景品名。⚠ `prizeLabel` が `null` なら **「何も出ない」**
    （⚠⚠ **文言をここに書かない**——063h が共有した定数を使う。設定画面のテスト抽選と**同じ言葉**であること）。
  - **レア** … ⚠ 別の列にしない。**結果の隣のバッジ**（`✨レア✨` ではなく画面の意匠に合わせる）。
    ⚠ 列を増やすと横に伸びて読めなくなる（この窓は配信中に開く）。
- ⚠⚠ **引いた人の行から視聴者詳細へ飛べるようにする**（貢献者一覧と**同じ導線**を再利用）。
  ⚠ **`viewers` に行が無い場合がある**（063h は FK を張らない）ので、
  **詳細が引けなかったときに画面が壊れないこと**（穴 C）。
- **空のとき**: 「ガチャはありません」の 1 行。
  ⚠⚠⚠ **「この配信より前の記録はありません」等の説明文を書かない**（注記全廃の決定）。
- **件数が多いとき**: ⚠ **画面側で直近 N 件に切り、切ったことを画面に出す**
  （062c が `list_stream_sessions` を直近 20 件に切ったときと**同じ作法**。Rust は触らない）。
  N は実装時に決めて**定数 1 か所**に置く。

### (3) テスト

- **frontend（vitest）**
  - 何も出なかった行が **「何も出ない」**として出る（⚠ 「ハズレ」という語が画面に無いことも固定）。
  - レアのバッジが出る／出ない。
  - 空のときの 1 行。
  - ⚠ **上限で切ったときに「切った」ことが画面に出る**。
  - ⚠⚠ **`list_gacha_draws` が失敗しても、課金・レイドの節は出る**（(1) の規律）。
  - ⚠ 既存ガード（**長い説明文を出さない**）に引っかからない。
- **Rust（cargo test）**
  - 並び順（`drawn_at` 降順）。
  - 別セッションの行が混ざらない。
  - `prize_label` が NULL の行が `None` として返る。

## このタスクでやらないこと

- **期間サマリー（[062d](062d-stream-history-filter.md)）へのガチャの合流**。
  ⚠ 申し送りだけ書く（**月別・年別で「誰が何を引いたか」を出すなら母集合の定義を先に決める**こと。
  062d が「配信別と月別で数字が食い違わないように定義を揃えろ」と申し送っているのと同じ問題が起きる）。
- **視聴者詳細（`ViewerDetailPanel`）にガチャ履歴を出す**こと。⚠ 要望は「配信サマリー」なので範囲外。
- **集計**（誰が何回引いたか・景品ごとの実測確率）。⚠⚠ **実測の相対確率は出さない**
  （[gachaDraw.ts](../../apps/desktop/src/screens/obs-effects/gachaDraw.ts) の穴 D の決定は不変）。
- **エクスポート／CSV**、**メールの導線**（[063g](063g-gacha-prize-mail-spike.md) の結論次第で 063j 以降）。
- **過去の配信への遡及**（記録は遡れない＝古い配信のサマリーは必ず空になる）。

## ⚠ 先に潰す穴

| 穴 | 中身 | 決め方 |
|---|---|---|
| **A** | **行数が多い配信** | 画面側で直近 N 件＋「切った」表示（上の (2)）。⚠ **再修正トリガー＝ N 件で足りないと言われたとき**（そのときは Rust 側にページングを入れる。⚠ DTO を先に触らない） |
| **B** | **時刻の扱い** | `drawn_at` は**端末が生成した RFC3339 で常に同じ形**（062c が `published_at` で困った「`Z` とオフセットが混ざる」問題は起きない）。⚠ **表示は既存の `fmtDateTime` を使う**（独自実装を作らない） |
| **C** | **`viewers` に行が無い視聴者** | 063h が FK を張らないので起こりうる。⚠ **一覧の表示は行が持つ `viewerName` だけで完結する**（JOIN しない）。詳細へ飛べなかったときは**開かないだけ**にし、画面を壊さない |
| **D** | **改名した視聴者** | 一覧は**抽選時点の名前**を出す（貢献者一覧は `viewers.name` ＝今の名前なので、⚠ **同じ画面に 2 つの規則が並ぶ**）。⚠⚠ **これは仕様である**——「その配信で誰が引いたか」は当時の名前が正しい。⚠ 説明文は書かない（注記全廃）ので、**テストで意図を固定する** |
| **E** | **CSS ガード** | `pnpm check:css`（生 hex 禁止等）に通ること。⚠ 既存の `summarySection` / 表のスタイルを**再利用**し、新しい意匠を発明しない |

## 完了条件

1. 配信サマリーに「ガチャ」節が出て、**引いた人・ガチャ・結果・時刻**が読める。
2. 何も出なかった抽選が **「何も出ない」**として並ぶ（⚠ 「ハズレ」と出ない）。
3. 行から視聴者詳細へ飛べる（⚠ 飛べないときも画面が壊れない）。
4. ガチャの取得に失敗しても、**課金・レイドの節は従来どおり出る**。
5. ⚠ **保存ポリシーを 1 ミリも動かしていない**（Rust の変更は**読み取り専用コマンド 1 本**だけ）。
6. **新規依存ゼロ・capability ゼロ・外部通信ゼロ**。
7. `docs/task-board.md` と親 [063](063-gacha-effect.md) が更新されている。
