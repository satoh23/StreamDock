## 目的

**ユーザーに `.css` ファイルを作らせない。** 手元にある CSS をそのままフォームへ貼り付け、
「取り込む」を押すだけでテーマとして保存できるようにする。

060d までは `@tauri-apps/plugin-dialog` の `open()` でファイルを選ぶ経路しか無く、
「CSS の文字列は持っているがファイルにはしていない」ケースで**ユーザーにファイルを作らせていた**。

## やったこと

### (1) Rust: コマンド 1 本（共通コアへの委譲）

- `overlay_theme::commands::import_overlay_theme_text(css, name)` を追加（**同期**）。
- `overlay_theme::service::import_pasted_text(dir, conn, raw_css, raw_name)` が
  **既存の `store_sanitized_css` へ委譲するだけ**。⚠ **検証を 1 行も再実装しない**
  （060b からの申し送りの核心。`exactly_one_place_sanitizes_and_exactly_one_place_writes` が
  「サニタイズは 1 か所・書き込みは 1 か所」を出現回数で固定している）。
- したがって貼り付け経路でも次がそのまま効く:
  名前検証（trim・空拒否・制御文字・80 コードポイント）／**256KB 上限**／本文の制御文字検査／
  **200 件上限**／外部参照の除去（fail-closed）／uuid 採番／書き込み → INSERT の順序／失敗時の掃除。
- **出自は `Local`**（`Snapshot` は 060c 専用）。⚠ `origin` は **service 側で定数として渡す**——
  `commands.rs` に `origin` の文字が現れると `the_theme_origin_is_never_settable_from_the_frontend` が落ちる。

### (2) ⚠⚠ 契約テストを「禁止」から「出現回数の固定」へ

`takes_no_arbitrary_path_or_content_from_the_frontend` は **`css: String` を全面禁止**していた。
これは §3「汎用の `write_file(path, content)` 型を作らない」を機械で守る番人で、
**本タスクはその番人を意図的に緩める作業**である。

- **禁止を消していない**——`css: String` の**出現回数を 1 に固定**した（2 本目が増えたら落ちる）。
- `content` / `bytes` / `data` は**引き続き全面禁止**（「汎用の書き込み」に見える命名を残さない）。
- `exposes_exactly_five_single_purpose_commands` は 5 → **6** へ（関数名は履歴として残す）。

**緩めてよいと判断した理由**:

1. **書ける場所が変わらない。** 保存先は `app_data_dir/themes/<uuid v4>.css` の固定形だけで、
   その組み立てにユーザー入力が 1 バイトも入らない（`the_storage_path_is_built_only_from_the_app_data_dir`
   が「`app_data_dir()` は 1 か所」「`join(THEMES_DIR)` は 1 か所」「ファイル名の結合は 1 か所」を固定）。
   ＝ §3 が禁じているのは「**書ける場所を呼び出し側が決める**」形であって、本文を渡せること自体ではない。
2. **中身は必ずサニタイザを通る**（外部参照を保存できない・取り除けない形は取り込み拒否）。
3. **上限がある**（256KB × 200 件）。アプリ定義コマンドは ACL 対象外＝全 4 窓から呼べるので、
   無制限にディスクが増える経路を作らないことが要る。

⚠ **攻撃面はファイル版より狭い**——`path` を取らないので、
UNC / ネットワークパス経由の egress も、「拡張子 `.css` に限定された任意ファイル読み取り」の合成
（060b review② の受容事項）も**増えない**。

### (3) frontend

- `overlayThemeApi.ts`: `importOverlayThemeText(css, name)` ＋ `themeCssError()` ＋ `cssByteLength()`。
  ⚠⚠ **サイズは UTF-8 バイト長で数える**（Rust は `css.len()`）。`css.length` は UTF-16 単位なので
  日本語コメント入り CSS で 3 倍近く食い違い、「入力できるのに保存できない」になる。
  ⚠ 060d の `THEME_NAME_MAX_CHARS`（コードポイント単位）とは**数える単位が違う**——
  Rust が名前は `chars().count()`、本文は `len()` で見ているため。**片方に揃えないこと。**
- `OverlayThemeCard.tsx`: **既定のフォームを貼り付けにした**（`useState<NameForm>({ kind: "paste" })`）。
  カードを開いた時点で貼って押せる。名前は空なら「デザイン N」（既存と重複しない番号）で保存する。
  ⚠ **名前を必須にすると「貼って押すだけ」にならない**ので、`paste` のときだけ空を許して既定値へ倒す。
  ⚠ ファイル選択は**副導線として残す**（既に `.css` を持っている人の手数を増やさない）。
- 取り込み後の**結果表示・プレビュー・削除・改名は 060d のものをそのまま共有**する
  （`runImport` は「どのコマンドを呼ぶか」だけを引数に取る形へ変えた＝経路が増えても表示の作法が分岐しない）。

### (4) §9

- CSS 本文は **state → invoke の 1 経路だけ**を通る。`console.*` はゼロのまま。
- ⚠ 失敗時は **Rust の固定文言をそのまま出す**（frontend で書き直さない）。
  Rust 側は `store_errors_never_carry_the_css_body_back_to_the_caller` で本文がエラーに載らないことを固定済み。
- ⚠ **入力欄（textarea）の中身は §9 の対象外**（ユーザー自身が貼ったもの。パスワード欄に打った文字が
  見えるのと同じ）。テストの判定も「**入力欄の外**に出ていないこと」にしてある。

## やらないこと

- **既存テーマの編集（貼り付けで上書き）** —— 別機能。今回は新規取り込みだけ。
- CSS のシンタックスハイライト・整形・エディタ機能。
- ファイル選択版の削除（副導線として残す）。

## ⚠⚠ 060c の代替ではない（本タスクの範囲を誤読しないこと）

⚠⚠ **[060c](060c-external-css-snapshot.md) は必須である。060e はその代替にならない。**

一時「外部 `@import` の中身はブラウザで開いてコピペすれば持ち込めるので 060c は不要かもしれない」と
書いたが、**これは誤りなので取り消した**（依頼者の指摘・2026-08-05）。理由:

- 依頼者のサンプル CSS は**意匠の実体が丸ごと外部 `@import` の中**にある。つまり 060c が payload そのもので、
  それを「ユーザーが毎回ブラウザで URL を開き、view-source してコピペする」に置き換えるのは、
  **機能を配ったことにならない**（手間の問題ではなく、成立していない）。
- 060 の目的は「**ユーザーが持っている CSS がそのまま使える**」ことで、
  ユーザーに前処理を要求した時点でその目的から外れる。
- ⚠ **スコープの判断は実装者がしてよい種類のものではない。**

**060e の位置づけ**: 「CSS の文字列は持っているがファイルにはしていない」人のための入口。
**060c と直交する**（どちらか一方があればよい、という関係ではない）。

## ⚠⚠ security-review②（第三者・2026-08-05）の結果

**判定「修正必須」。ただし修正必須は 060e 本体ではなく、同じ working tree に入っていた
[B]（060d の自己レビュー→自己修正ぶん）で出た**——つまり **論点 2（自己レビューには第三者の追認が要る）
の懸念が的中した**。

- ⚠⚠ **`cssScope.ts` の走査器は 1 回目の修正でも閉じていなかった**（脱出 2 系統。仕様トークナイザ
  `@csstools/css-tokenizer` と `css-tree` を oracle に実測。**どちらも 060b のサニタイザを
  `stripped_count=0`・無改変で通過**し、末尾に `}` を 1 つ足すと `unclosedBlockDepth` も 0 ＝警告も出ない）:
  ① **`\` ＋改行は valid escape ではない**（css-syntax-3 §4.3.7＝ delim トークン）のに ident へ飲み込んでいて、
  直後の `url(` の不透明扱いが起動しなかった
  ② **at-keyword の名前のエスケープを復元していなかった**ため、`@med\69 a`（＝ブラウザにとって `@media`）が
  グループ規則と認識されず、中の規則に前置されなかった。あわせて `@starting-style` が allow-list から漏れ。
  → **修正済み**（`isIdentStart` / `readIdent` / `atRuleName` / `GROUP_AT_RULES`）。回帰 13 件追加。
- ⚠⚠ **教訓**: この走査器は「1 か所直したら閉じた」と考えないこと。**自作コーパスと目視では 2 回とも漏れた。**
  検証は**仕様トークナイザ／独立実装パーサとの差分**でしか成立しない。
- ✅ **§3 の緩め方（本タスクの中心論点）は妥当と追認された。** 本文経由で保存先・ファイル名・件数・サイズを
  動かす反例は構成できず、契約テストも骨抜きになっていない（`production_sources()` が `//` 行を落とすので
  doc コメントの `css: String` はカウントされない）。⚠ 残る穴＝ `text:` / `body:` / `source: String` は
  依然素通り（060e 以前からの穴。専用 newtype なら型で固定できる＝別タスク候補）。
- ⚠ **§5 の「②は①より攻撃面が狭い」は片側だけ正確**だったので軸を分けて書き直した
  （`path` 由来のものは増えないが、**本文の内容支配＝任意バイト列の永続化**は増える。受容）。
- 品質: **貼りかけの CSS が「キャンセル」「改名の成功」「ファイル取り込みの成功」で消えるデータロス**を修正
  （申し送り 2 の既知欠陥。実際にはキャンセル以外の 2 経路でも起きていた）。`NameForm` の死に枝 `| null` を除去。
  `insertAdjacentHTML` 系を (10-i) の禁止へ追加。`@property` / `@counter-style` を文書グローバル名へ追加。
  `contain: paint` のサポート下限（Safari 15.4+ / macOS 12.3+）を明記。
- 実測で確定した判断: **`cssError` の `useMemo` は不要**（256KB で 0.14ms/回）／
  **`import_overlay_theme_text` の同期化は妥当**（256KB の敵対的入力でサニタイズ 2〜3ms）。
