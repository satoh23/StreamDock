## 目的

作ったガチャを**実際にイベントで回す**。[061b](061b-monetary-effect-builtin.md) の発火層に相乗りし、
「このイベントが来たらこのガチャを 1 回引き、当たった景品のエフェクトを出す」を成立させる。

## 現在の前提（調査結果・実コード）

- [061b](061b-monetary-effect-builtin.md) の `effectTrigger.decideEffects(added, updated)` が
  `EffectRequest[]` を返す形になっており、**多重発火の抑制を既に持っている**:
  - `updated`（[043e](043e-youtube-jewels-combo-fidelity.md) の Jewels combo 再送）から出さない
  - 同一投稿者の `gift` をバッチ内で 1 件に畳む（[043a](043a-monetary-ingestion-fidelity.md) の N+1）
  - バースト上限（1 バッチから最大 N 件）
  ⚠ **これらをガチャで作り直さない。** ガチャは「どのエフェクトで出すか」を差し替えるだけ。
- [061d](061d-effect-template-ui.md) で「イベント種別 → エフェクト（なし / 組み込み / テンプレート）」の
  割り当てが localStorage に保存されている。**ガチャはこの選択肢に 1 種類増える**（「ガチャ」）。
- ⚠ **チャンネルポイントは扱えない**（親 063 の決定・新規スコープが要る）。
- ⚠ 使えるトリガーは `CommentEventType`（chat / superchat / subscription / membership / gift /
  donation / jewels）と [062a](062a-twitch-raid-ingestion.md) の `raid`。

## このタスクでやること

### (1) 抽選ロジック（新規 `gachaDraw.ts`・純関数）

- `draw(prizes: GachaPrize[], rng: () => number): GachaPrize | null`
  - 重み付きランダム（累積和 ＋ `rng() * total`）
  - `prizes` が空、または重みの合計が 0 なら **`null`**（呼び出し側が発火しない）
  - ⚠ **`rng` を注入可能にする**（テストのため）。既定は `Math.random`
- ⚠ **浮動小数の境界**に注意する。`rng()` が 1.0 を返す実装は無いが、
  累積和との比較で**最後の景品が選ばれない／範囲外になる**バグが起きやすい。
  **境界（`rng() = 0` と `rng()` が 1 に極めて近い）をテストで固定する。**
- ⚠ **天井・確定枠・在庫・履歴による確率変動は作らない**（親 063 の決定）。

### (2) トリガー割り当て（[061d](061d-effect-template-ui.md) の拡張）

- イベント種別ごとの選択肢に **「ガチャ」＋ガチャ名**を足す。

| イベント | エフェクト |
|---|---|
| スーパーチャット / ビッツ | なし / 組み込み / テンプレート名… / **ガチャ名…** |

- ⚠ **既存の割り当て保存形式を壊さない**。値の形を
  `{ kind: "none" | "builtin" | "template" | "gacha", id?: string }` のような union にし、
  **旧形式（テンプレート id の文字列）を読めるようにする**か、キー名を変える
  （[046a](046a-viewer-pin-comment.md) の申し送り：「破壊的なスキーマ変更は version 欄ではなく**キー名を変える**」）。
  **どちらにするか実装時に決めてコメントに残す。**
- ⚠ **景品 0 件のガチャは割り当てられない**（[063a](063a-gacha-definition-editor.md) の (5)）。
  選択肢に出さないか、選んだら警告を出す。

### (3) 発火層への接続（`effectTrigger.ts`）

- `decideEffects` が「このイベントの割り当てはガチャ」と分かったら、
  `draw()` を呼んで**当たった景品のエフェクト**を `EffectRequest` に載せる。
- ⚠ **抽選は 1 イベント 1 回**。バッチ内で同じイベントが複数あっても、
  061b のバースト上限と畳み込みを**先に**通してから抽選する。
  **順序を間違えると「畳んだはずのギフトで 5 回引く」ことになる。**
- `EffectRequest` に景品名を載せるかを決める。
  ⚠ **載せるなら [061c](061c-effect-template-import.md) の `text.template` の変数が
  `{name}` / `{amount}` / `{event}` の 3 つに固定されている**ので、
  **景品名を出したいなら 4 つ目の変数（`{prize}`）を足す必要がある**。
  → **足す場合は [061c](061c-effect-template-import.md) の検証（未知変数の拒否）も同時に更新すること**。
  ⚠ **これは 061c の完了条件を書き換える変更**なので、忘れずに両方直す。

### (4) ⚠ 回しすぎ防止（荒らし耐性）

- **`chat`（通常コメント）をトリガーにできると、誰でも無限に回せる。**
  演出が壊れるだけでなく、配信が荒らされる。
- 対策（**既定を安全側にする**）:
  - **`chat` トリガーの既定は「無効」**。選ぶこと自体はできるが、選んだら警告を出す。
  - **クールダウン**（例 30 秒）を設定できるようにする。`chat` トリガーでは**必須**にする。
  - ⚠ **`chat` を選んだ場合はキーワード指定を必須にする**か（「!gacha」等）を検討する。
    **推奨＝キーワード必須**。無条件だと全コメントで回る。
    ⚠ ただし**キーワード判定を作ると「条件を書く」に近づく**ので、
    **単純な前方一致 1 本だけ**にする（正規表現も複数条件も作らない＝親 063 の設計目標）。
  - **同一視聴者の連続当選を防ぐ**（例：同じ人は N 秒に 1 回まで）。
    ⚠ **これは §9 に触れる**（視聴者 id を一時的に保持する）。**メモリ上のみ・永続化しない**こと。
- ⚠ **課金トリガー（superchat 等）にはクールダウンを既定で付けない**
  （お金を払った人の演出が出ないのは体験として悪い）。

### (5) テスト

- `gachaDraw.test.ts`（新規）:
  - 重み 1/3/6 で、`rng` を固定値にしたときに期待どおりの景品が出ること
  - **境界**: `rng() = 0` → 最初の景品／`rng()` が 1 に極めて近い → **最後の景品**（範囲外にならない）
  - 空配列・合計 0 → `null`
  - 大量試行（`rng` を疑似乱数で固定シード）で分布が重みに概ね一致すること
- `effectTrigger.test.ts` の拡張:
  - **畳み込み・バースト上限を通してから抽選される**こと
    （⚠ コミュニティギフト N+1 で N+1 回引かない）
  - `updated` で引かないこと
  - 景品 0 件のガチャで発火しないこと
  - **クールダウン**が効くこと（`chat` トリガーで連投しても 1 回）
  - **同一視聴者の連続当選抑制**が効くこと
- ⚠ **視聴者 id が永続化されていない**ことをテストで固定する（§9）
- **ミューテーションで実効性を確認**する。最低限、抽選を畳み込みの前に移す変異と、
  クールダウンを外す変異でレッドになること。

## セキュリティ制約（docs/security.md 準拠）

- **外部通信ゼロ**（§1）。
- ⚠ **§9**: 回しすぎ防止のために視聴者 id を保持するが、**メモリ上のみ・永続化しない**。
  **抽選履歴・当選者を DB や localStorage に保存しない。**
  ⚠ 保存すると [046a](046a-viewer-pin-comment.md) の §9 追補（第三者の個人データの端末保存）の対象になり、
  軽レビューでは済まなくなる。
- **入力検証**（§8）: キーワードはユーザー入力なので長さ上限・制御文字拒否。
  ⚠ **正規表現として解釈しない**（ReDoS の経路を作らない・単純な前方一致のみ）。
- **乱数は演出用**（`Math.random` で足りる）。⚠ 暗号用途ではないことをコメントに明記する
  （後から「不正防止のために `crypto.getRandomValues` にすべきでは」と言われたときの答えを残す）。
- **frontend のみ**。Rust / sidecar / capabilities / `tauri.conf.json` / 依存は差分ゼロ。`csp: null` 不変。
- ログに景品名・当選者・視聴者 id を出さない（§9）。
