## 目的

ガチャを「引いた感」のある演出にする。現状（[063b](063b-gacha-draw-and-triggers.md) 完了時点）は
**当たった景品のエフェクトが即座に出るだけ**で、抽選している感じがない。

**抽選中 → 結果**の 2 段にして、配信画面で「回っている」ことが伝わるようにする。

## 現在の前提（調査結果・実コード）

- [061a](061a-effect-overlay-window.md) のエフェクト窓（`effect-overlay`）で
  [061b](061b-monetary-effect-builtin.md) が `EffectRequest` を 1 件ずつ描いている。
  表示は既定 5 秒程度でフェードイン/アウト。**同時再生はしない**（1 度に 1 つ）。
- [061c](061c-effect-template-import.md) のテンプレートは
  `media`（画像/GIF/APNG/WebM）＋ `sound` ＋ `layout` ＋ `text` を持ち、
  **data URI で webview に渡され、描画側のガードが `data:` 以外を弾く**。
- [063b](063b-gacha-draw-and-triggers.md) の抽選は**発火の時点で結果が確定している**
  （`draw()` が同期の純関数）。
  → ⚠ **演出は「結果が決まった後に、決まっていないふりをする」**もの。
  **抽選のタイミングを演出に合わせて遅らせない**（遅らせると 061b のバースト上限・
  クールダウンとの整合が崩れる）。
- ⚠ **同時再生しない設計**なので、**演出中に次のガチャが来たときの扱い**を決める必要がある。

## このタスクでやること

### (1) 演出の 2 段構成

```
[抽選中]（1〜2 秒）  →  [結果]（景品のエフェクト・既定 5 秒）
```

- **抽選中**の見せ方は**組み込み 1 種**で足りる（第 1 弾）。
  ⚠ **凝らない。** 「ガチャガチャのハンドルが回る」ような凝った演出はテンプレートに任せる。
  組み込みは「景品名がシャッフル表示される」程度で十分（実装が軽く、確率の演出としては十分伝わる）。
- **結果**は [061b](061b-monetary-effect-builtin.md) / [061d](061d-effect-template-ui.md) の
  既存の描画をそのまま使う（景品に割り当てたテンプレート、または組み込み意匠）。
  ⚠ **描画を 2 実装に分けない。**
- **抽選中の時間は設定可能**にする（0 = 演出なしで即結果）。
  ⚠ **既定は短め（1.5 秒程度）**。長いと配信のテンポが悪くなる。実値と理由をコメントに残す。

### (2) 抽選中の演出用テンプレートを許す（任意）

- ガチャ定義に「抽選中エフェクト」を 1 つ持てるようにする（[063a](063a-gacha-definition-editor.md) の
  `gachas` テーブルに `spin_template_id` を `ensure_column` で追加）。
  - 未設定なら組み込みのシャッフル表示
  - 設定されていれば [061c](061c-effect-template-import.md) のテンプレートを再生
- ⚠ **`spin_template_id` にも FK を張らない**（[063a](063a-gacha-definition-editor.md) と同じ・
  実在しなければ組み込みへフォールバック）。
- ⚠ **`text.template` の `{prize}` は抽選中には使えない**（結果を先に見せてしまう）。
  抽選中テンプレートで `{prize}` が使われていたら**空文字に置換する**か、
  **取り込み時に警告する**。**どちらにするか実装時に決めてコメントに残す。**

### (3) ⚠ 演出中に次のガチャが来たときの扱い

エフェクト窓は**同時再生しない**設計なので、次のどれかを選ぶ。**理由をコメントに残すこと。**

- **(a) 現在の演出を最後まで見せ、次はキューに 1 件だけ積む**（推奨）
  - ⚠ キューの上限は 1〜2 件。溜めると配信のテンポが崩れ、数分後にエフェクトが出続ける
    （[061b](061b-monetary-effect-builtin.md) がバースト上限で捨てているのと同じ思想）
- (b) 現在の演出を打ち切って次を出す（連続で来ると何も見えない）
- (c) 次を捨てる（課金で回されたのに何も出ないのは体験として悪い）

⚠ **[061b](061b-monetary-effect-builtin.md) のバースト上限が既に効いている**ので、
ここに来る件数はもともと絞られている。**二重に捨てすぎないよう、061b の上限と整合を取ること。**

### (4) 音

- 抽選中の音と結果の音を**別に鳴らせる**ようにする（テンプレートの `sound`）。
- ⚠ **抽選中の音が結果の音と重ならないよう、抽選中の音は結果に入る前に止める。**
- ⚠ [059](059-notification-sounds.md) の通知音とは**別系統**（同時に鳴りうる）。
  ⚠ **投げ銭でガチャを回すと、投げ銭通知音（059b）＋抽選中の音＋結果の音が重なる**。
  実機で確認し、うるさければ**設定で「ガチャ中は通知音を鳴らさない」を足すか、本人に相談する**。
  ⚠ **これは実機でしか分からない**ので、確認コマンドに必ず入れる。

### (5) テスト

- 演出の 2 段が順に出ること（抽選中 → 結果）
- 抽選中の時間が 0 のとき、**即座に結果が出る**こと
- ⚠ **結果が抽選前に漏れない**こと（抽選中の表示に景品名が出ない・`{prize}` が空になる）
- 演出中に次が来たとき、(3) で決めた挙動どおりになること（キュー上限を超えたら捨てる）
- 実在しない `spin_template_id` が組み込みへフォールバックすること
- 抽選中の音が結果の前に止まること
- **ミューテーションで実効性を確認**する。最低限、抽選中に景品名を出す変異でレッドになること。

## このタスクでやらないこと

- **抽選ロジック**（[063b](063b-gacha-draw-and-triggers.md)）。演出は結果が決まった後の見せ方だけ。
- ⚠ **抽選のタイミングを演出に合わせて遅らせること**（バースト上限・クールダウンとの整合が崩れる）。
- **テンプレートの取り込み**（[061c](061c-effect-template-import.md)）。
- 凝った組み込み演出（ハンドル回転・カプセル落下など）。**テンプレートに任せる。**
- 複数エフェクトの同時再生・重ね合わせ。
- 演出中のユーザー操作（スキップボタン等）。エフェクト窓は表示専用・非フォーカス。
- 連続演出（10 連ガチャ）。
- 天井・確定枠の演出。

## セキュリティ制約（docs/security.md 準拠）

- **外部通信ゼロ**（§1）。メディアは [061c](061c-effect-template-import.md) が保証する data URI のみ。
- ⚠ **描画側の `data:` ガードを必ず通す**（[061c](061c-effect-template-import.md) の最終防波堤・036a と同型）。
- ⚠ **`dangerouslySetInnerHTML` を使わない。** `{name}` / `{prize}` の差し替えはテキストノードとして描く
  （投稿者名は第三者の自由入力）。
- **§9**: 演出で**新しい保存をしない**。景品名・当選者を DB や localStorage に残さない
  （[063b](063b-gacha-draw-and-triggers.md) の決定と同じ）。
- **frontend のみ**（`spin_template_id` の列追加だけ Rust に触れる）。
  capabilities / `tauri.conf.json` / 依存は差分ゼロ。`csp: null` 不変。
- 生 hex を書かない（トークンのみ）。
- ログに景品名・当選者を出さない（§9）。
