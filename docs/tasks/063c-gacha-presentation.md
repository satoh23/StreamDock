## 目的

ガチャを「引いた感」のある演出にする。

現状（[063b](063b-gacha-draw-and-triggers.md) 完了時点）は **当たった景品に紐づく OBS のソースが
即座に 1 回鳴るだけ**で、⚠ **抽選している感じがない**。しかも ⚠⚠ **その OBS ソースはユーザーが
自分で作らないと 1 つも無い**——「ガチャを作ったのに、鳴らすものが無い」状態から始まる。

⇒ **StreamDock 側に組み込みの演出を持ち、OBS へ自動反映する。**

## ⚠⚠⚠ これは [061h](061h-builtin-effect-removal.md) の**部分的な反転**である（理由を残すこと）

061h は「組み込みエフェクト」を**廃止**した。理由は依頼者の運用方針:

> **エフェクトは各々が使いたいものを import して使う。組み込みは不要。既定は非表示。**

⚠⚠ **本タスクはその逆を言っている。** ⇒ **なぜ区別できるのかを記録に残さないと、
次に誰かが「061h に反している」と言って消しにくる。**

| | 061h が消した組み込み | 本タスクが持つ組み込み |
|---|---|---|
| 対象 | **投げ銭の演出**（スパチャ・サブスク等） | **ガチャの演出**（抽選中 → 結果） |
| 依頼者の判断 | 「各々が好きなものを使う」＝**自作のハードルが低い**（1 枚絵で足りる） | ⚠⚠ **「ユーザーが作成するのは難しい」**（抽選中の動きが要る） |
| 既定 | ⚠ **出さない**（`{kind:"none"}`） | ⚠ **上書きが無ければ組み込みが出る**（下記 (3) で厳密化） |

⚠⚠⚠ **061h が「最悪」と定めた形を、向きを変えて持ち込まないこと。**
061h の最悪は「**テンプレートが壊れているのに組み込みが出て、動いているように見える**」だった。
⇒ **本タスクの最悪は「上書きを設定したのに組み込みが出る」**である。**両方向とも塞ぐ**（下記 (3)）。

## ⚠⚠ [064](064-obs-source-effects.md) の**どこを反転し、どこを反転しないか**

⚠ 依頼者の「ここのみ例外で」を、**曖昧なまま実装しないこと**。

| 064 が捨てたもの | 本タスク |
|---|---|
| ユーザーが**動画/画像を StreamDock に取り込む**（[061c](061c-effect-template-import.md) のテンプレート） | ❌ **戻さない。** 戻すと 100MB 級 data URI・ディスク 4.25GiB・マジックバイト検査・symlink 拒否・第三者 JSON が**全部復活する**（064 が「大幅に軽くなる」と数えた面がそのまま戻る） |
| StreamDock が**自前の窓に描く**（[061a](061a-effect-overlay-window.md) / [061k](061k-stage-overlay-window.md)） | ✅ **捨てていない。** ステージ窓は現存し、061l の配信イベントを描いている |
| ユーザーが **OBS 側にソースを置く**（064 の方式） | ✅ **維持する**（＝「こだわりたい人の上書き」がそのままこれ） |

⇒ ⚠⚠ **例外なのは「組み込みの意匠を持つ」という一点だけ**である。

## ⚠⚠⚠ 決めること

### (1) 演出の 2 段構成

```
[抽選中]（既定 1.5 秒）  →  [結果]（景品名・既定 5 秒）
```

- ⚠⚠ **抽選は「発火の時点でもう終わっている」**（`drawGachaPrizeIndex` は同期の純関数）。
  ⇒ **演出は「結果が決まった後に、決まっていないふりをする」**もの。
  ⚠⚠⚠ **抽選のタイミングを演出に合わせて遅らせないこと**——遅らせると
  063b のバースト上限・クールダウン・畳み込みとの整合が崩れる。
- ⚠ **凝らない。** 組み込みは「**景品名がシャッフル表示される**」程度で十分
  （確率の演出としては十分伝わるし、実装が軽い）。
- **抽選中の秒数は設定可能**にする（**0 ＝ 演出なしで即結果**）。⚠ 既定は短め（テンポが悪くなる）。

### (2) ⚠⚠⚠ 結果をどうやってステージ窓へ渡すか（**本タスク最大の論点**）

⚠⚠⚠ **絶対にやってはいけないのは「ステージ窓が自分でもう一度抽選する」**——
`Math.random()` が 2 回независに走るので、**演出は A が当たったと言っているのに OBS は B を出す**。
⇒ **結果は「伝える」しかない。**

| 案 | 評価 |
|---|---|
| **(a) Tauri の窓間イベント**（`emitTo("stage-overlay", …)` → `listen`） | ✅ **推奨。** 永続しない／他窓に撒かない／⚠⚠ **未認証の loopback WS からは到達できない**／capability 追加ゼロ。⚠ 規律（上記）の更新が要る |
| **(b) localStorage ＋ `storage` イベント** | ⚠ 既存パターン（061l の開催キー）だが、**永続する**ので「**窓を開き直したら古い当たりが出る**」を自前で塞ぐ必要がある（nonce ＋ 時刻）。⚠ `storage` は**全窓へ撒く**（コメント窓・固定窓も受け取って捨てる） |
| **(c) sidecar の WS でブロードキャスト** | ❌ ⚠⚠⚠ **却下。** loopback WS は**未認証**なので、**ブラウザで開いた任意のページが「大当たり！」を配信画面に出せる**。塞ぐには 4 本目のチケットが要り、**割に合わない** |

⚠ **(a) を採るなら決めること**: イベント名／payload の形（⚠ **景品名は入るが第三者データは入らない**）／
**ステージ窓が閉じているときに捨てられる**こと（⚠ 演出が出ないだけで、**OBS のソースは鳴る**＝本線を止めない）。

#### ⚠⚠⚠ レビュー Q-12（追記 1）: **`decideFireSourceNames` の戻り値を広げる必要がある。持ち主を先に決めること**

いまの戻り値は **`string[]`（OBS のソース名だけ）**で、⚠ **景品名を運べない。**
「〇〇 が当たりました」を出すには**発火層の戻り値を広げる**ことになる。

⚠⚠ **そして [063f](063f-gacha-chat-output.md) も同じ拡張を必要としている**（文面に景品名／当選者名を入れるため）。
⇒ ⚠⚠⚠ **2 つの計画が同じ型を独立に広げようとしており、持ち主が決まっていない。**
**先に着手したほうが形を決め、もう一方はそれに乗ること**（2 通りに広げると、片方だけが知らない
フィールドを持つ・片方だけ §9 の判断が抜ける、が起きる）。
⚠ 広げるときも **`EffectRequestBase` を丸ごと復活させないこと**（063b 段 1-b の返済が無かったことになる）。

#### ⚠⚠⚠ レビュー Q-12（追記 2）: **食い違いは「再抽選」以外にも経路がある**

(2) の冒頭は「絶対にやってはいけないのは**ステージ窓が自分でもう一度抽選する**」としているが、
⚠⚠ **食い違いを作る経路はもう 1 本ある**——**演出は「A が当たった」と出したのに OBS が鳴らない**ケース:

- 景品の `sourceName` が OBS から消えていると、**064a の実在照合（`GetInputList`）が弾く**
  （`"そのソースが OBS に見つかりません"`）。⇒ **演出だけが当たりを宣言する。**

⚠ 本文が扱っているのは**逆向き（ステージ窓が閉じている＝演出が出ないが OBS は鳴る）だけ**である。
⇒ **決めること**: 発火の成否をステージ窓へ伝えるか／演出を**OBS の結果より後**に出すか／
**演出側でも「そのソースが見つかりません」を出す**か。⚠ **本線（OBS）を止めない**制約は維持すること。

#### ⚠⚠⚠ 穴 α（2026-08-23・実コードで発見）: **窓を開く契機を新設すると security.md §1 のガードが壊れる**

[`docs/security.md`](../security.md) の **064e 追補**は、044a 例外「**ユーザーが明示的に有効化した時のみ
