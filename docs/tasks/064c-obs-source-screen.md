## ⚠⚠ 着手時に見つかっていた「画面が積極的に嘘をつく」箇所

**`listSources` は失敗しても成功しても空配列を返していた。**

| 場所 | 実態 |
|---|---|
| `obs-client.ts` の `listSources` | 接続失敗は `catch` で `onState("failed", …)` して **`[]` を返す** |
| `index.ts` の `obs-list-sources` | 成功・失敗どちらも `obs.sources` を `{sources: []}` で送る |
| `CommentViewerApp.tsx` の `onObsSources` | 「**失敗時も空配列で来る**ので、そのまま書き戻して 0 件として見せる」と自分で書いてあった |

⇒ **OBS が起動していないとき、main 窓はこう出していた**:

> 鳴らせるソースが見つかりませんでした。OBS のシーンに「メディアソース」か「画像」を追加してください。

⚠⚠ **OBS が落ちているだけなのに「OBS にソースを追加しろ」と間違った対処へ誘導していた。**
061a レビュー Q-1（「配信中には表示されません」）／061i レビュー S-1（廃止したトグルを指す案内）に続く
**同じ失敗モードの 3 度目**である。

⚠ **これは表示の直しだけでは潰せない**——main 窓に届く情報が「空配列」しか無かったため。

## やったこと

### ① sidecar: `obs.sources` に `ok` を載せた（＝失敗と 0 件を分ける）

- `listSources` の戻りを `ObsSourceListResult = { ok: boolean; sources: ObsSourceInfo[] }` へ
- **`ok:false` を返すのは OBS へ辿り着けなかったときだけ**／繋がって 0 件は **`ok:true` ＋ 空配列**
- ⚠ `onState("failed", …)` は**残した**（コメビュ窓ツールバーの赤字＝既存の観測点を壊さない）

⚠⚠ **`obs.state` で代替しなかった理由**: あちらは comments / pinned / stage と**共有**の状態通知で、
「固定コメントの自動追加が失敗した」のか「一覧が取れなかった」のかを受け手が判別できない
（061e レビュー Q-5 が既に受容している限界）。**一覧要求への直接の返事**にだけ載せるのが正しい。

⚠ 絞り込みは純関数 `toObsSourceListResult` へ切り出した——`listSources` 本体は実 OBS が要って
`test-obs-client.mjs` から呼べないため。**「0 件でも `ok:true`」と allow-list の絞り込みだけは
実機を待たずに固定できる**ようにしてある（allow-list の絞り込みは 064a 以来**検査ゼロ**だった）。

### ② desktop: 安全側を 2 か所で揃えた

| 層 | 規則 |
|---|---|
| WS 境界（`commentStream.ts`） | `typeof p?.ok === "boolean"` でなければ **`false`** |
| 保存層（`overlaySettings.ts`） | 同上（⚠ このキーは**他窓からも書ける**） |

⚠⚠ **倒し先を間違えないこと。** `true` へ倒すと、0 件のときに
「OBS のシーンにソースを追加してください」＝**064c が潰した当の誤案内が復活する**。
`false` 側の誤りは「OBS を確認してください」で済み、ユーザーの行動が無害である。

### ③ 画面: 状態を 7 つに分け、必ず 1 つだけ出す

`obsSourceListStatus.ts`（純関数・新規）が決める:

| 状態 | 判定 | 出すもの |
|---|---|---|
| `no-viewer` | `viewerOpen === false` | コメントビューアを開くと取得できます |
| `never` | 一覧が無い | まだ取得していません／ボタンを押してください |
| `pending` | 依頼済みで返事待ち | OBS から取得しています… |
| `timeout` | 8 秒待った | 応答がありませんでした |
| ⚠ `disconnected` | `ok === false` | **OBS が起動しているか、WebSocket が有効かを確認** |
| `empty` | `ok === true` かつ 0 件 | OBS のシーンにメディアソースか画像を追加 |
| `ready` | 1 件以上 | 一覧（＋「HH:MM 時点」） |

⚠ **順序に意味がある**——`no-viewer` は他のどれより先（依頼が誰にも届かないので、
8 秒待って `timeout` を出すのでは遅い）。
⚠ **`viewerOpen === null`（未取得）を `no-viewer` にしない**（2 秒ポーリングの初回で点滅する）。

**足したもの**:
- ⚠⚠ **並びを反転**（OBS のソース → 条件）。**逆順だと空の `<select>` を先に見せて理由を下に書く**ことになる。
  ⚠ 061p が条件を先頭に置いた根拠は「取り込みは最初の 1 回だけ」だったが、**064d でその取り込みが消えた**。
- ⚠ `viewerOpen` を `ObsEffectsScreen` から渡す（**既に 2 秒ポーリングしている値**＝ invoke もタイマーも増えない）
- ⚠ **「HH:MM 時点」**（`OBS_SOURCE_LIST_KEY` の JSDoc が 064a から要求していたのに、
  画面に出していた場所が 1 つも無かった）。⚠ `toLocaleTimeString` を使わない（環境で表記が変わる）
- ⚠ `REQUEST_TIMEOUT_MS = 8000`（sidecar の `CONNECT_TIMEOUT_MS` 4 秒 ＋ 往復の余裕）。
  **`storage` はベストエフォート**なので、出口が無いと「取得しています…」が**セッション中ずっと残る**
- ⚠ 「まだ確認用の機能です」を外した（064d 以降、これが**唯一の出し方**）

**足さなかったもの**:
- **条件行の「試す」ボタン** … テスト発火の持ち主は一覧行の「1 回鳴らす」1 か所のまま
  （⚠ 同じ操作を 2 か所に置くと、どちらが正か分からなくなる。2 枚が隣接するので実害も小さい）。
  ⚠ **再修正トリガー＝「条件ごとに試したい」と言われたとき**
- **画面を開いたときの自動取得** … ⚠ **`docs/security.md` §1「ユーザーが明示接続した時のみ」の姿勢を
  変えないため**（画面を開くだけで OBS へ TCP 接続を張ることになる）。⚠ 手動ボタンのまま
- **「コメントビューアを開く」ボタンの 2 つ目** … 既存の前提案内が持ち主（§1 の停止導線と同居）

## ⚠ コメビュ窓が閉じていても一覧は隠さない
