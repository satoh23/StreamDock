## 目的

依頼者の要望⑦「**たぬえさというツールのガチャガチャをもっと簡単に作れる機能**。
たぬえさの方で設定するのではなく、こちらで自前のガチャガチャのエフェクトを作るのが良いと思う。
たぬえさがどのような形で設定するのかを調べ、**それよりかなり簡単に作成できるようにする**。
たぬえさは使いにくかったり、**if 文をたくさん書かないといけない**らしくそれを不満に思っている配信者が多いもよう」を実装する。

**「たぬえさより簡単」が唯一の成功条件**。機能の多さではなく、**設定手順の少なさ**で勝つ。

## 現在の前提（調査結果）

### たぬえさ3 について（Web 調査・[063s](063s-tanuesa-gacha-spike.md) で一次情報を確認する）

- **たぬえさ3 は Twitch 専用の無料自動化 BOT**。チャット・チャンネルポイント・ビッツ・サブスクに反応して
  画面に画像・音・動画を出す。
- **ガチャの設定手順**（記事ベース・要一次確認）:
  1. トリガーを選ぶ
  2. **抽選箱**を作る
  3. **抽選タグ**を作る
  4. ⚠ **タグをコピー＆ペーストで増やす**
  5. 各タグにメディア（画像/音声）を設定
  6. 保存
- **OBS への出し方**: OBS のソース → ブラウザ → 「ローカルファイル」→ たぬえさ3 フォルダの
  **`forOBS3.html`** を選ぶ。
- OBS WebSocket 経由でシーン切替・ソースの表示/非表示も操作できる。

### ⚠ 「if 文をたくさん書く」の実体は未確認

依頼者の情報は伝聞（「らしい」）。**条件式を書かされるのか、上記 4. の「タグをコピペで増やす」手作業を
指しているのか**が分かっていない。**ここを取り違えると、解こうとした問題を解かないまま作ることになる。**
→ **[063s](063s-tanuesa-gacha-spike.md) で確定させる。**

### StreamDock 側の前提

- [061](061-obs-effects.md) で**エフェクト窓・発火層・テンプレート形式・割り当て UI** が完成している。
  ガチャは**その上に「抽選」を足すだけ**で済む。
- ⚠ **OBS への出し方が違う**: たぬえさ3 はブラウザソース（`forOBS3.html`）、
  StreamDock は**ウィンドウキャプチャ**（[044s](044s-obs-websocket-spike.md) で方式 A を実測決定）。
  → **たぬえさ3 の資産（`forOBS3.html` や設定ファイル）はそのまま使えない。**
- ⚠ **StreamDock は YouTube にも対応している**（`CommentViewDto` で正規化済み）。
  **たぬえさ3 は Twitch 専用**なので、**ここが最大の差別化点**になりうる。
- ⚠ **チャンネルポイントは扱えない**。Twitch のチャンネルポイント（`channel.channel_points_custom_reward_redemption.add`）は
  **新規 EventSub 購読＋新規スコープ**が要る＝既存ユーザーの再ログインが必要になる
  （[043a](043a-monetary-ingestion-fidelity.md) の `bits:read` の先例）。
  **本親では対象外**とし、必要になったら別タスクで本人に確認する。

## 確定した方針

### (1) 「たぬえさより簡単」を設計目標として明文化する

- **1 画面・1 表で完結**させる。景品を 1 行ずつ足すだけ。
- ⚠ **「条件を追加」「タグをコピペ」に相当する操作をゼロにする。**
  たぬえさ3 の不満点がそこにあるなら、**そこを消すことが機能の芯**。
- **確率は自動計算して常に表示する**（重みを入れたら「12.5%」が横に出る）。
  合計 100% にする作業をユーザーにさせない。
- ⚠ **[063s](063s-tanuesa-gacha-spike.md) の結論で「簡単にならない」と分かったら、設計を作り直す。**

### (2) ガチャは [061](061-obs-effects.md) のエフェクト基盤に乗る

- 景品 1 つ = [061c](061c-effect-template-import.md) のテンプレート 1 つ（または組み込み意匠）。
- 発火は [061b](061b-monetary-effect-builtin.md) の `effectTrigger` に相乗りする。
  ⚠ **多重発火の抑制（combo 再送・コミュニティギフト N+1・バースト）は 061b が既に持っている**ので、
  ガチャで作り直さない。
- 表示は [061a](061a-effect-overlay-window.md) のエフェクト窓。**新しい窓を作らない。**

### (3) 抽選は「重み付きランダム」1 種類だけ

- ⚠ **天井・確定枠・在庫・履歴による確率変動は作らない**（第 1 弾では）。
  複雑さがそのまま「たぬえさと同じ」になる。
- ⚠ **乱数の再現性は要らない**（配信演出なので）。ただし**テストのために乱数を注入可能にする**。

### (4) トリガーは既存のイベントのみ

- 使えるのは `CommentEventType`（chat / superchat / subscription / membership / gift / donation / jewels）と
  [062a](062a-twitch-raid-ingestion.md) の `raid`。
- ⚠ **チャンネルポイントは対象外**（新規スコープが要る）。**UI にその旨を書く**
  （たぬえさ3 の主用途がチャンネルポイントなら、ここは正直に伝えないと期待外れになる）。
- ⚠ **「コメントでガチャ」は荒らし耐性が要る**。誰でも無限に回せると演出が壊れるので、
  **クールダウンか課金限定**を既定にする（[063b](063b-gacha-draw-and-triggers.md) で確定）。

## 横断セキュリティ方針（docs/security.md 準拠）

- **外部通信ゼロ**（§1）。**たぬえさ3 の設定ファイル・`forOBS3.html` を読み込まない**
  （第三者コード実行になる＝[061](061-obs-effects.md) の決定と同じ）。
- **第三者コードを実行しない。** 景品は [061c](061c-effect-template-import.md) の
  宣言的テンプレート（アセット＋`manifest.json`）のみ。
- **ガチャ定義は端末内 SQLite に保存**（§9）。⚠ **第三者の個人データを含まない**
  （景品名・重み・テンプレート id はユーザー自身が作ったもの）＝
  [062b](062b-stream-session-recording.md) と同じく §9 では軽い。
- **入力検証は Rust 側で必ず行う**（§8）。景品名の長さ・制御文字・重みの範囲・景品数の上限。
- **新規スコープ・新規購読ゼロ**（チャンネルポイントを対象外にする理由のひとつ）。
- **capability を増やさない**・`csp: null` 不変・**新規依存ゼロ**。
- ログに景品名・当選結果・視聴者名を出さない（§9）。
