## 目的

**1 つのガチャを、複数の条件から使い回せるようにする。**

依頼者の要望（2026-08-23）:

> ガチャは何回も同じ設定をするのは大変なので、ガチャ自体のテンプレートを作れた方が便利かなと思うんですが
> つまり、テンプレート1のガチャはスパちゃとビッツがきた時に発火するというようにOBSエフェクトで設定できると言ったような

⇒ **ガチャに名前を付けて一覧で持ち、条件の `<select>` はそれを指すだけにする。**

## 発端（⚠ これは 063a が明示的に先送りした点である）

[063a](063a-gacha-definition-editor.md) は景品を**割り当てそのものに直付け**した:

```ts
EffectGacha = { kind: "gacha"; prizes: readonly GachaPrize[] }
```

保存も条件ごと（`event:superchat` / `event:jewels` / `kw:1` …）なので、
⚠⚠ **同じガチャをスパチャとビッツに設定するには、景品表を 2 回入力することになる。**
⚠⚠⚠ **さらに悪いのは編集側**——景品を 1 つ直すと 2 箇所直す必要があり、
**片方を忘れると確率が静かにずれる**（画面のどこにも「ずれている」と出ない）。
条件は最大 **26 本**（課金イベント 6 ＋ キーワード [`KEYWORD_CONDITION_MAX`]＝20）なので、増えるほど破綻する。

⚠ **これは 2 箇所で予告されている**（＝設計上の想定内であり、いま「再修正トリガー」を引いた形）:

- [063a](063a-gacha-definition-editor.md) (1): 「**再修正トリガー＝ガチャを複数保存して使い回したくなったとき**」
- `effectSelectValue.ts` の `GACHA_VALUE`: 「⚠⚠ **プレフィックス付きにしない**（`gacha:<id>` にしない）——
  景品はこの割り当て自身が配列で持っており、**指す先の id が存在しない**」

⇒ **本タスクは「`gacha:<id>` にする」ことそのものである。**

## 現在の前提（調査結果・実コード / 2026-08-23）

⚠ **本節は推測を含まない。すべて実コードを読んで確認した。**

### 🟢 クールダウンは設計変更なしで正しく動く（⚠ 最重要）

`effectTrigger.ts` の `decideEffects` は、クールダウンを **`match.conditionId` でキーにしている**
（`state.lastConditionAt.get(match.conditionId)`）。**割り当ての中身ではキーにしていない。**

⇒ **1 つのガチャをスパチャとビッツで共有しても、両者のクールダウンは独立したまま**である。
「片方が回るともう片方が止まる」は起きない。⚠ **発火層に一切触らずに共有が成立する。**

### 🟢 選択値の仕組みがそのまま使える

`effectSelectValue.ts` は既に `obs:<name>` という**接頭辞つきの選択値**を持ち、
組み立て（`effectSelectValue`）と分解（`effectSelectAssignment`）が 1 か所に閉じている。
`gacha:<id>` は**同じ形をもう 1 本足すだけ**で、`slice` を新しく書く必要が無い。

参照先が消えたときの警告も **`isObsSourceMissingFromList` と同じ形**で書ける
（064b が「OBS 側で名前を変えた／消した」に対して既に作っている規律）。

### 🟠 前方互換の既存の仕組みが、今回だけ効かない

`parseAssignment` の「**未知の `kind` → 出さない**」は **`kind` が変わるときの話**である。
今回は **`gacha` という既知の `kind` の中身が変わる**ので、このガードを素通りする。
⇒ ⚠⚠ **読み込み時の明示的な移行が要る**（下記 (3)）。**061h / 064d のように「移行コードを書かずに済む」形にはならない。**

⚠ 逆方向（**旧ビルドが新形式を読む**）は安全側に倒れる——`parseGachaPrizes(undefined)` が `[]` を返し、
`{kind:"gacha", prizes:[]}`＝「景品がありません」になる。**静かに違うものが出ることは無い。**
⚠⚠ **ただし片道の破壊がある**（下記 穴 P）。

### 🔴 「テンプレート」という語は使えない

[064d](064d-remove-template-import.md) が **`effect_templates` テーブル・`template_id`・
`EffectAssignment` の `template` variant・`isEffectTemplateId` を全削除済み**である。
⇒ docs 上「テンプレート」＝**消した取り込み機能**を指す。同じ語を使うと、
⚠ **旧 063a 本文が `template_id` 前提で壊れていたのと同じ種類の混乱**を作る。

⇒ **決定（依頼者・2026-08-23）: 「ガチャ」に名前を付けて一覧にする。「テンプレート」という語を一切使わない。**
UI の文言は「ガチャを選ぶ」「ガチャを作る」。

### 🟢 共通の下部は既に空である（⚠ 063a 穴 G の根拠が消えていた）

[063a](063a-gacha-definition-editor.md) は 穴 G で「3 枚目のタブにすると
**共通の下部＝出力窓の設定がガチャにも掛かって見える**」としてタブ追加を却下した。
⚠⚠ **その共通の下部は [064e](064e-ui-adjustments.md)（「OBS へ自動で反映」カード削除）と
[064f](064f-screen-layout.md)（§1 停止導線の削除）で既に全部消えており、
いま `Tabs` の下に残っているのはコメントだけ（JSX 要素ゼロ）である。**

⇒ **却下の理由は失効しているが、結論は変えない。** 空いた下部にガチャ一覧を置くほうが、
「**両タブから参照される共有物**」という位置づけが素直に伝わる（3 枚目のタブにすると
「コメント用でもイベント用でもない 3 種類目のエフェクト」に見える＝ 嘘になる）。

⚠ **決定（依頼者・2026-08-23）: タブは 2 枚のまま。共通の下部に「ガチャ」セクションを置く。**

### 🟢 OBS ソース一覧は既に画面が持っている

`ObsEffectsScreen` が `obsSources` の状態を持ち、`ObsSourceCard`（表示専用）へ渡している（064f）。
⇒ ガチャセクションにも**同じ状態を渡すだけ**でよい。
⚠ **一覧の取り直しボタンは持たせない**（`ObsSourceCard` が唯一の持ち主・063a と同じ規律）。

## なぜ 063b より先か（⚠ 実装順の根拠）

**保存形が変わるからである。** [063b](063b-gacha-draw-and-triggers.md) は
「割り当てを読んで抽選を回す」実装なので、**本タスクを後に回すと発火の経路を 2 回触る**ことになる。
⚠⚠ さらに悪いのは、**ガチャが実配信で稼働している状態で保存形を移行する**ことになる点である
（移行を間違えると「昨日まで動いていたガチャが今日は何も出ない」になり、原因が画面から読めない）。

⇒ **本タスクを先に済ませ、063b は最初から `gachaId` を引く形で 1 回だけ書く。**
⚠ デメリット（＝受容する）: **ガチャが実際に発火するのを見るのが 1 タスク分後ろにずれる。**

## このタスクでやること

### (1) 保存形（⚠ **キーを 2 本に分ける**）

```ts
/** 063d: 名前付きのガチャ 1 件。⚠ 景品の型（`GachaPrize`）は 063a のまま無改変。 */
interface GachaDefinition {
  id: string;                        // uuid v4（`crypto.randomUUID()`）
  name: string;                      // 1〜GACHA_NAME_MAX_LENGTH 文字（⚠ 空は不可＝選択肢に出るため）
  prizes: readonly GachaPrize[];     // 既存の parseGachaPrize をそのまま通す
}

/** 割り当て（⚠ `prizes` が `gachaId` に変わる）。 */
type EffectGacha = { kind: "gacha"; gachaId: string };
```

- **新しい保存キー**: `stream-dock.obs-effects.gachas`（`overlaySettings.ts` に定数を追加）。
  ⚠ **条件のキー（`EFFECT_ASSIGNMENTS_KEY`）と分ける理由**＝ 1 本にすると
  「条件を全部消したらガチャまで消える」が起きる（`saveEffectConditions` は
  **条件が空になるとキーごと削除する**）。
- **`<select>` の値**: `gacha:<id>`（`GACHA_SOURCE_PREFIX = "gacha:"`）。
  ⚠ **`obs:` とまったく同じ作法**で `effectSelectValue.ts` に閉じる。
  ⚠⚠ **`GACHA_VALUE = "gacha"`（接頭辞なし）は廃止する**——その JSDoc（「指す先の id が存在しない」）が
  **本タスクで嘘になる**ので、注記ごと差し替えること。

### (2) 上限（⚠ すべて根拠を書くこと）

| 定数 | 値 | 根拠 |
|---|---|---|
| `GACHA_DEFINITION_MAX` | **10** | 共通の下部に一覧として並ぶので「**1 画面で読める**」（`GACHA_PRIZE_MAX = 20` と同じ規律）。⚠ **上限は後から上げるほうが安全**（下げると既存の設定が落ちる）。再修正トリガー＝「ガチャが足りない」と言われたとき |
| `GACHA_NAME_MAX_LENGTH` | **24** | `<select>` の選択肢と一覧の行に収める。`GACHA_PRIZE_NAME_MAX_LENGTH` と同値（**別定数にする**——収まる場所が違うので、片方だけ変えたくなる） |
| 景品の上限 | 20（既存） | `GACHA_PRIZE_MAX` を**そのまま使う**（ガチャごとに 20 件） |

⚠ **超過は丸めず落とす**（`parseGachaPrize` と同じ規律）。⚠ **名前だけは空を許さない**
（景品名は空を許すが、ガチャ名は**選択肢に出る**ので空だと選べなくなる）。

### (3) 移行（⚠⚠⚠ **本タスク最大の危険箇所**）

**読み込み時に 063a 形式（`{kind:"gacha", prizes:[…]}`）を見つけたら、ライブラリへ移して読み替える。**

- `prizes` が 1 件以上でも 0 件でも、**必ずライブラリ項目を 1 件作る**
  （0 件でも作る理由＝ 063a が「**景品 0 件でも `gacha` のまま保つ**」と決めており、
  「ガチャにした」というユーザーの意思を捨てないため）。
- 名前は `移行したガチャ 1`, `2`, …（⚠ **上限に達したら移行せず「出さない」へ倒し、画面に理由を出す**）。
- ⚠⚠ **同じ景品構成の inline ガチャが複数あっても、まとめない**——
  「別々に設定した 2 つ」なのか「同じつもりの 2 つ」なのかは**保存値からは判別できない**。
  勝手にまとめると**片方を編集したらもう片方も変わる**という、ユーザーが頼んでいない共有を作る。
  ⇒ **1 つずつ移す。まとめるのはユーザーの操作に任せる**（画面で選び直せば済む）。
- ⚠ **移行は読み込み時にメモリ上で行い、書き戻すのは次にユーザーが何か操作したとき**
  （`normalizeGachaWeights` を消したのと同じ規律＝**読むだけでは保存値を書き換えない**）。

### (4) 参照が壊れたときの扱い（⚠ 064b と同じ形にする）

- `gachaId` がライブラリに無い → **条件行に警告を出し、発火は「出さない」へ倒す**。
  文言は 064b の「OBS にこの名前のソースが見つかりません…」と**同じ構造**にすること。
  ⚠ **黙って別のガチャへ化けさせない**（064b が `<option>` を自前で出しているのと同じ理由）。
- **ガチャを削除するとき** → ⚠⚠ **使っている条件を列挙して確認ダイアログを出す**
  （「このガチャは『スーパーチャット・ビッツ』『キーワード 1』で使われています。削除しますか？」）。
  ⚠ **黙って壊さない。** 削除後は上記の警告が出る状態になる。

### (5) UI（⚠ タブは増やさない）

**`ObsEffectsScreen` の共通の下部**（タブ 2 枚の外・いま空になっている場所）に「ガチャ」セクションを置く:

```
┌─ OBSエフェクト ──────────────┐
│ [課金イベント] [キーワード]      │  ← タブ 2 枚のまま
│ ────────────────────────── │
│ スパチャ  → [ガチャ: 大当たり ▼] │
│ ビッツ    → [ガチャ: 大当たり ▼] │  ← 同じものを指す
│ サブスク  → [obs: kirakira ▼]   │
│ ────────────────────────── │
│ ▼ ガチャ                        │  ← ここに新設（両タブの外）
│   大当たりガチャ    [編集][削除] │
│   深夜用ガチャ      [編集][削除] │
│   [＋ ガチャを作る]              │
│   ┌ 大当たりガチャ ───────────┐ │
│   │ 景品名  出る確率  当たったら │ │  ← 063a の GachaPrizeTable を
│   │ 大当たり 10%  kirakira ▼  │ │     そのまま流用
│   │ 合計 40.0% / 何も出ない 60%│ │
│   └──────────────────────────┘ │
└────────────────────────────┘
```

- ⚠⚠ **`GachaPrizeTable` は作り直さない。** 063a のものを**そのまま**使う
  （`effect` prop が `EffectGacha` から `GachaDefinition` に変わるだけ）。
  ⚠ **063a-3 の芯（各行が独立・補正しない・分母 1000 固定・はずれは `-1`）を 1 つも壊さないこと。**
- ⚠ 条件行の下に開いていた表は**閉じる**（編集の入口をガチャセクションの 1 か所に寄せる）。
  ⇒ 条件行に残るのは `<select>` と「参照が壊れている」警告だけになる。
- ⚠ `labelPrefix` は**ガチャ名**にする（条件名ではなくなる）。
  ⚠⚠ **`＋ 景品を追加` / `テスト抽選` の `labelPrefix` を落とさないこと**
  （2 つ以上のガチャを同時に開くなら同名ボタンが並ぶ・レビュー Q-063a-7 と同じ罠）。
- ⚠ 「配信中の自動抽選はまだ動きません」の注記は**063b まで残す**（063a の規律）。

## このタスクでやらないこと

- ⚠⚠ **Rust には一切触らない**（新規テーブル・新規コマンド・capability の追加は**ゼロ**）。
  063a と同じく **frontend のみ**。⚠ **`gachas` / `gacha_prizes` の 2 テーブル案を蒸し返さない**
  （旧 063a 本文の案・穴 F で却下済み）。
- **抽選の本発火**（[063b](063b-gacha-draw-and-triggers.md)）。本タスクの後も**ガチャは発火しない**。
- **ガチャの共有・エクスポート・取り込み**。⚠⚠ [064d](064d-remove-template-import.md) が
  取り込み機能を**全削除した**ので、その形を持ち込まない。
- **ガチャごとのクールダウン設定**。⚠ クールダウンは**条件が持つ**（061j）。
  ガチャに持たせると「条件のクールダウン」と「ガチャのクールダウン」が**2 か所に割れる**。
- **抽選履歴・当選者の保存**（§9・063a の「やらないこと」を継承）。

## セキュリティ制約（docs/security.md 準拠）

- ⚠⚠ **新規 egress ゼロ・新規 capability ゼロ・新規依存ゼロ・Rust 差分ゼロ**（§1／§3／§10）。
  `capabilities/`・`tauri.conf.json`・`Cargo.toml`／`Cargo.lock`・`package.json`／`pnpm-lock.yaml` は**差分ゼロ**。
- **§8**: 検証は **frontend のみ**（063a と同じ根拠が**そのまま生きる**）:
  1. **保存時と読み込み時の両方**で同じ `parseGachaPrize` を通す
  2. OS へ渡る値の壁は**従来どおり sidecar の 2 枚**（`isAllowedObsSourceName` ＋ `GetInputList` との実在照合）
  3. `security.md` がユーザー自身の UI 設定値を保存ポリシーから除外している
  - ⚠ **`id` は `crypto.randomUUID()` で採番し、ユーザー入力を id にしない**（名前と id を分ける）。
  - ⚠ **名前も制御文字を落とす**（`sanitizeGachaPrizeName` と同じ規律・上限が違うので別関数）。
- **§9**: ⚠⚠ **第三者の個人データは 1 バイトも入らない**（保存するのはガチャ名・景品名・重み・OBS ソース名だけ）。
