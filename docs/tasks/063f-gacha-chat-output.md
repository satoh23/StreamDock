## 目的

[063t](063t-gacha-output-types-spike.md) が「ガチャの出力の型は 4 つあり、StreamDock は 1 つしかできない」
ことを確定させた。できない 3 つ（**チャット完結型 / 併用型 / 景品配布型**）の原因は 1 つで、
**チャットに書き込む経路が 1 本も無い**ことだった。

⇒ [066](066-chat-send.md) が経路を作った（段 1 ＝ 送信の基盤、段 2 ＝ 宛先の門）。
**本タスクは、その経路にガチャの当選結果を繋ぐ。**

## 現在の前提（実コード調査済み・2026-08-23）

- **発火元は [`effectFire.ts`](../../apps/desktop/src/screens/obs-effects/effectFire.ts) の
  `decideFireSourceNames`** ——当たりを決めている唯一の場所。
  ⚠⚠ **戻り値は現在 `string[]`（OBS のソース名だけ）である。**
- ⚠ **投稿者名は発火層にもう存在しない。** 063b 段 1-b が `EffectRequestBase` の 6 フィールド
  （`id` / `name` / `amountText` / `message` / `eventLabel` / `tone`）を**全廃した**ので、
  文面に投稿者名を入れるなら**返す型を増やし直す**ことになる。
  ⚠⚠⚠ **それは「§9 の面を広げる」変更である**（下記「決めること (2)」）。
- **送信は [`commentStream.ts`](../../apps/desktop/src/features/comment-viewer/commentStream.ts) の
  `sendChat(message, expectedChannel)`** ——`Promise<{ok, reason?}>` を返す。
  ⚠ `expectedChannel` は**宛先ではなく期待値**で、⚠⚠ **宛先として使う配線を書かないこと**（066 S-2）。
- ⚠⚠ **スロットルは sidecar 側にある**（最短 3 秒／30 秒に 5 通／**直前と同じ本文を拒否**）。
  ⚠⚠⚠ **`CHAT_MIN_INTERVAL_MS = 3_000` の JSDoc が「再修正トリガー＝自動送信（063b）を繋ぐとき」と

- ⚠ **トークン取得の限界も再評価が要る**。`getValidAccessToken` は
  「アクセストークンが生きている間は非破壊」であって、**期限切れ＋ refresh 失敗なら `tokenStore.clear`
  ＝ keychain 削除へ倒れる**。⚠⚠ 段 1 で許容できたのは「**送信は取得セッション稼働中にしか起きない**」
  ＝人が押したときだけ、という前提があったから。
  ⚠⚠⚠ **`twitch-chat-sender.ts` の JSDoc が「再修正トリガー＝自動送信を繋ぐとき。
  期限切れなら交換せず再ログインを促して終わるラッパを検討すること」と明記している。**

## 決めること（着手時に潰す穴）

### (1) ⚠⚠ 文面のテンプレート

- 最小構成は「**景品名だけ**」（例: `🎉 大当たり！ 〇〇 が出ました`）。
- ⚠ **`{景品名}` などの差し込み記法を作るなら、記法の持ち主を 1 か所にすること**
  （2 か所で解釈すると片方だけ壊れる。063a の「確率の持ち主は 1 本だけ」と同じ規律）。
- ⚠⚠ **本文の検証は `isAllowedChatMessage` が既に持っている**（型・空・500 文字・**制御文字と改行の拒否**）。
  ⚠⚠⚠ **本タスクで別の検証を新設しないこと**（2 通りに書くと片方だけ緩む）。
- ⚠ **はずれ（`-1`）のとき何を書くか**も決めること（**書かない**が既定として素直）。

### (2) ⚠⚠⚠ 当選者名を出すか（**独立した判断**）

⚠⚠ **§9 の面が変わる。** 第三者の表示名が「端末内で持ち回る」から
**「配信のチャットへ公開する」**へ移る。⚠⚠⚠ **書き込みは視聴者に見えて、あとから消せない。**

- **出さない場合** … `effectFire.ts` の戻り値は今のまま（ソース名＋景品名）でよい。
  ⚠ **063b 段 1-b の返済を取り消さずに済む**。
- **出す場合** … 戻り値に投稿者名を戻すことになる。
  ⚠ そのとき **`EffectRequestBase` を丸ごと復活させないこと**（要るのは名前 1 つで、
  金額・配色・種別ラベルは 1 つも要らない。**6 つ戻すと 063b の返済が無かったことになる**）。
- ⚠ **既定は「出さない」が安全側**。出すなら**トグルにして既定 OFF**。

### (3) ⚠⚠ 送信の失敗をどう見せるか

⚠⚠⚠ **自動送信はユーザーが画面を見ていないときに走る。** ⇒ **失敗をその場で見せる相手がいない。**

- ⚠ **本線（OBS の演出）を止めないこと**（チャットが送れなくても景品は鳴るべき）。
- ⚠⚠ 「黙って効かない、を作らない」（061a Q-1）と両立させる形を決めること
  （候補＝**コメビュ窓に最後の失敗理由を残す** ／ 設定画面に出す。⚠ **§9: 本文は残さない**）。

### (4) ⚠⚠ スロットルを決め直す

段 1 の値（最短 3 秒）は「**手動のテスト送信しかない**ので詰める理由が無い」という根拠で置いたもの。
⚠ **ガチャは 5 秒に最大 3 件まで発火しうる**（063b のバースト上限）ので、
**3 秒間隔だと 3 件目が落ちる**。⇒ ⚠⚠ **落ちた分をどうするか**（捨てる／まとめる）を決めること。
⚠ **Twitch の 20 通/30 秒より十分低く保つ**（BAN 側へ倒れない）という制約は変えない。

### (5) ⚠ トークンの扱い（上記「現在の前提」の最後）

**期限切れ＋ refresh 失敗で keychain が消える経路**を、自動送信でも許すか。
⚠⚠ 許さないなら「期限切れなら交換せず、再ログインを促して終わる」ラッパが要る。

### (6) ⚠⚠⚠ 自動送信で `expectedChannel` に何を渡すか（レビュー Q-12 の追記）

`ChatSendFrame.expectedChannel` は **optional ではなく必須**なので、自動送信も必ず何かを渡す。
⚠⚠ ところが **自動送信には「押した瞬間の画面」が存在しない**ので、S-2b の突き合わせの意味が変わる:

| 渡す値 | 意味 |
|---|---|
| **frontend の `channel` state**（推奨） | 「**この窓が繋いでいるつもりの配信**と sidecar の宛先が同じ」——⚠ 窓が別の配信へ繋ぎ直したのに sidecar が古い宛先を握っている、は依然として捕まえられる |
| `""` | ⚠ `sendChat` の空チェックで**送信そのものが落ちる**（＝「黙って送れない」事故になる） |
| 突き合わせを外す | ❌ ⚠⚠⚠ **門を 1 枚減らす変更**（`chat-send-frame.ts` の JSDoc が明示的に禁じている） |

⇒ ⚠ **決めずに実装すると、実装者が場当たりで選んで門が静かに無効化される。**
⚠⚠ **`expectedChannel` は「宛先」ではなく「期待値」**であることも変わらない（**宛先として使わない**）。

### (7) ⚠ はずれを書くなら戻り値の型が要る

`decideFireSourceNames` の戻り値は `string[]` で、⚠⚠ **はずれは「要素が出ない」としか表現されない**
——**「はずれた」と「そもそもガチャが発火していない」を呼び出し側から区別できない。**
⇒ (1) の「はずれのとき何を書くか」で**書く**を選ぶなら、**戻り値の型を広げる必要がある**
（⚠ (2) および [063c](063c-gacha-presentation.md) と**同じ型を広げる**ので、**持ち主を 1 つに決めること**）。
⚠ **既定の「書かない」を選ぶなら型は今のままでよい。**

#### ⚠⚠⚠ 2026-08-23 決着: **戻り値の形は [063c](063c-gacha-presentation.md) が決める。本タスクはそれに乗ること。**

**先に着手したほうが形を決める**という前提で、063c を先に着手した（段 1 完了・段 2 で型を広げる）。
⇒ ⚠⚠ **本タスクで `decideFireSourceNames` の戻り値を独立に広げないこと**
（2 通りに広げると「片方だけが知らないフィールドを持つ」「片方だけ §9 の判断が抜ける」が起きる）。

063c 段 2 が置く形（⚠ **確定は段 2 の実装時**。着手時に `effectFire.ts` の JSDoc を必ず読み直すこと）:

```ts
export type GachaPrizeOutput =
  | { kind: "builtin" }
  | { kind: "obs-source"; sourceName: string };

export type EffectFireResult =
  | { kind: "obs-source"; sourceName: string }                      // 条件が直に OBS ソースを指した
  | { kind: "gacha-prize"; prizeName: string; output: GachaPrizeOutput };  // ガチャで当たった
```

- ⚠ **関数名は `decideFireResults` へ改名される**（戻り値が「ソース名」でなくなるため）。
- ⚠⚠ **`EffectRequestBase` は復活させない**（063b 段 1-b の返済を取り消さない）。
  ⇒ 上記 (2) で**当選者名を出す**を選ぶなら、**`EffectRequestBase` ごとではなく
  「投稿者名 1 フィールド」を `gacha-prize` に足す**こと。
- ⚠⚠⚠ **はずれ（`-1`）の variant は 063c 段 2 では作らない**
  （あちらは「はずれにも演出を出したいなら**はずれの行を足す**」という 063a の設計に乗るため）。
  ⇒ **本タスクが「はずれを書く」を選ぶなら、3 本目の variant を足すのは本タスクの担当**である。
  ⚠ そのときも**上の 2 本の形は変えない**こと。

## ⚠ 実機確認（依頼者の環境で行う）

1. トグル OFF のまま当たりを引く → ⚠ **チャットに何も出ない**（既定 OFF の担保）
2. ON にして当たりを引く → **チャットに 1 通流れる**／**OBS の演出も出る**
3. ⚠ **連続で引く** → スロットルで落ちるぶんが出る。⚠⚠ **落ちても OBS の演出は出続ける**
4. ⚠ **取得を停止してから引く** → チャットには出ない（宛先が `null`）。⚠ OBS は出る
5. ⚠ 旧トークン（`user:write:chat` 無し）で引く → **本線が止まらない**こと
6. ⚠ `lsof -i` で **`api.twitch.tv` 以外の外部 ESTABLISHED が増えない**こと
